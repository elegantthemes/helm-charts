# DeepHive admission regression checks

Run `python3 tests/deephive-admission/run.py` from this repository with Helm,
Python/PyYAML and Go available. This renders the disabled-by-default chart using
synthetic settings and evaluates its admission expressions with pinned CEL-Go.
It runs `check.py`, `render.py` and `reader.py`, including all reader CEL cases.
It never installs a policy or contacts a cluster. Dependencies are test-only.

`pod.json` is a representative manifest generated by DeepHive's `sessionPod`,
with the API server's default service account populated. Keep it aligned when
that pod contract changes. Checks cover a valid session, forbidden mounts,
credentials, identities, host access, labels and image replacements, plus cleanup
of an older approved image and metadata-only updates. Kubernetes API schema and
live admission enforcement remain separate cluster acceptance checks.

Extra session metadata is allowed, including Full-mode and API-added topology
labels. Required release/session identity remains exact; worker/reader/Redis/DNS
selector labels are forbidden, and an optional worker-mode label must be `full`.

Run `python3 tests/deephive-admission/render.py` for release-name collisions,
quoted identifiers, Secret-revision rollouts, readiness, pre-pull taints and direct egress
lookup configuration. This is rendering validation, not deployed acceptance.

Increment `fullWorker.runnerSecretRevision` and upgrade Helm after rotating
an existing runner Secret in place, or explicitly restart `<release>-full-worker`.
The chart does not watch external Secret changes automatically. Configure
`fullWorker.prepullTolerations` for the dedicated node's scheduling taints.

Session pods must carry the chart's `app.kubernetes.io/instance` release label.
Before upgrading an older runner/chart that created unlabeled pods, drain those
sessions while the old policy still permits cleanup; do not strand them behind
the new release-scoped admission policy. This is a Phase 4 rollout gate.

Phase 3 runner upgrades require `fullWorker.approvedBootstraps` entries for
the pinned session image and every retained active/compatible image. Use each
reviewed image manifest's actual bootstrap/runtime identity; fixture hashes in
`values.json` are synthetic. Drain sessions whose approved identity cannot be
retained before upgrading. Protocol 2 is available for an explicit drain, but
Phase 3 routing requires protocol 3.

When private evidence is configured, supply `evidenceReadSecretRevision`. Rotate
the external read Secret, increment this revision and upgrade Helm to restart
consumers before revoking the old credential. The chart does not watch that
external Secret automatically. Runner write credentials follow the existing
`runnerSecretRevision` rotation procedure.

Observation requires a `runnerSecretRevision` value. Increment it and upgrade
Helm after rotating the observation token: both runner and consumer templates
include this revision, so both processes reload the token.

Routing requires distinct ReadWriteOnce claims for Lite and Full, mounted at
the same absolute canonical root. Set the Lite claim and mount via
`WORKSPACE_CLAIM_NAME` and `WORKSPACE_ROOT`, and the Full claim and mount via
`fullWorker.workspaceClaim` and `fullWorker.workspaceRoot`. Pin Lite with
`NODE_SELECTOR_HOSTNAME` and retain Full's dedicated `fullWorker.nodeName`.

The credential-free source seed lives under the Lite mount, for example
`/workspace-root/seed`. Lite scratch stays outside the workspace root.
The private transfer copies stopped Lite source before Full starts and returns
stopped Full edits before releasing its owner. In staging, verify both claims
bind on their intended nodes and exercise a full round trip with unpublished
changes. See the [workspace cutover guide](../../charts/deephive/remove-juicefs.md).

Public origins use lowercase DNS hosts matching `VIRTUAL_HOST`. Use ports
1–65535 for a nondefault port and omit port 443 and leading zeroes. Evidence
reader credentials use a dedicated Secret. Verify read-only IAM in staging.
