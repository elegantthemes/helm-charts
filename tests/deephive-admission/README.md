# DeepHive admission regression checks

Run `python3 tests/deephive-admission/check.py` from this repository with Helm,
Python/PyYAML and Go available. This renders the disabled-by-default chart using
synthetic settings and evaluates its admission expressions with pinned CEL-Go.
It never installs a policy or contacts a cluster. Dependencies are test-only.

`pod.json` is a representative manifest generated by DeepHive's `sessionPod`,
with the API server's default service account populated. Keep it aligned when
that pod contract changes. Checks cover a valid session, forbidden mounts,
credentials, identities, host access, labels and image replacements, plus cleanup
of an older approved image and metadata-only updates. Kubernetes API schema and
live admission enforcement remain separate cluster acceptance checks.

Run `python3 tests/deephive-admission/render.py` for release-name collisions,
quoted identifiers, Secret-revision rollouts, readiness, pre-pull taints and proxy
lookup configuration. This is rendering validation, not deployed acceptance.

Increment `fullEnvironment.runnerSecretRevision` and upgrade Helm after rotating
an existing runner Secret in place, or explicitly restart `<release>-runner`.
The chart does not watch external Secret changes automatically. Configure
`fullEnvironment.prepullTolerations` for the dedicated node's scheduling taints.

Session pods must carry the chart's `app.kubernetes.io/instance` release label.
Before upgrading an older runner/chart that created unlabeled pods, drain those
sessions while the old policy still permits cleanup; do not strand them behind
the new release-scoped admission policy. This is a Phase 4 rollout gate.
